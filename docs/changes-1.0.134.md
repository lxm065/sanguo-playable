# 1.0.134 即时难度计算

移除小游戏开战入口的多轮预演和整军中遮罩，直接进入正式战斗。旧模拟器校准代码迁至tools/offline-balance，仅供开发分析，不进入发布包。player-combat-context继续用于正式战斗与快速属性查询，未修改真实技能、伤害或奖励机制。

enemy-light-balance对双方每名单位各计算一次面板属性，汇总生命、攻击、攻速、防御和常规天赋的近似静态强度；装备进阶、天赋树、羁绊及VIP走已有共用属性入口。复杂控制、治疗、召唤和技能循环不做战斗预演。

固定曲线：第二阶段普通0.85、精英1.00、Boss1.08，每增加阶段加0.05，同阶段路线最多加0.03。最终倍率=曲线×双方静态强度比的0.6次方，强度比限制0.25至4，倍率限制0.25至3。培养补偿不完全抵消玩家培养优势。全部数值集中在enemy-light-balance-config。

首次开战锁定轻量计算结果；重试不重算；新关重新算。旧calibration快照在下一次开战一次性迁移，敌军身份、人数、等级、装备数量均不变，待领奖战报及第一阶段保护不变。

557项测试通过，覆盖正式开战仅调用一次真实模拟、无预演模块引用、静态计算纯读取、阶段及路线单调曲线、培养增益有界、旧缓存迁移及重试锁定。24种桌面场景单次计算1至33毫秒；这不是手机端耗时承诺。

开发侧仍以90/75/60且每阶段降5个百分点为长期目标，不再保证单关精确胜率。离线1920场固定样本的培养组仍普遍较容易，表明静态估算不等价于包含全部技能的胜率；需要结合真实阵容反馈调固定系数，不能声称已精确达到目标。证据evidence/light-balance-1.0.134.json，工具tools/check-light-balance-1134.cjs。

架构：线上仅保留小型属性估算模块，昂贵模拟完全隔离到开发工具；后续优先用多阵容离线样本标定配置，不再把概率搜索放回开战路径。
