# 1.0.284 存档同步静默重连

2026-11-01。截图中的“存档与账号 / 网络连接中断 / 退出 / 重试”来自运行中心跳或存档提交失败。旧实现一次失败立即锁定并弹出原生模态框，后续心跳仍会重复触发。

## 当前行为

- 临时心跳、提交失败只在后台重试；5、10、20、30秒退避，最长30秒。网络重新连接、回到前台可立即核验。并发入口共享同一恢复请求，不叠加心跳或新建登录。
- 最近有效核验的45秒租约内可以继续本机事务，本机主档与完整幂等提交日志正常落盘。提交响应丢失时复用原编号与原快照，新操作进入下一批，不改写在途数据。
- 超出租约，或切回前台尚未核验，变更操作在执行前暂停。画面上沿只显示一行状态文字；不弹退出/重试框，不关闭宝藏、领奖、布阵等当前界面。恢复后自动同步并开放操作，不自动重放被拒绝的点击。
- 开场核对账号/云档时网络中断同样静默退避，显示真实连接状态，不冒充资源100%完成，也不创建离线空档覆盖旧进度。
- 顶号、登录过期、存档冲突、本机存储故障仍停止保存，只提示一次；不会通过自动重新登录抢回会话，不静默覆盖不同进度。原有冲突双选与恢复副本保留。
- 切后台前尽力提交，后台不主动重连；旧前台迟到的心跳不得放行新前台。释放实例时取消定时器和自身监听。

策略、时长、提示文案与状态文字位置均在 `game/play/cloud-save-config.js` 集中配置。临时失败的状态、网络恢复与幂等提交由协调器负责，领域事务只检查写入许可，视图只负责轻量状态与必要决策。

## 后续架构建议

如需在长期离线时仍允许完整游玩，应单独设计服务端可核验的离线操作日志、奖励幂等与分叉合并规则，再调整45秒写入租约。仅延长租约会增加两端并行产生本机进度的窗口。后续可将错误分类与重试调度抽成独立策略端口，复用于排行榜和要塞同步，同时保留各自队列和持久化边界，避免一处失败影响其他功能。
