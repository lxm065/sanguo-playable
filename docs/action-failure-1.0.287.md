# 1.0.287 通用操作失败卡顿排查

日期：2026-11-01。

## 确认的问题

除已修复的满员拖拽外，远征的通用 `act`、经典页面动作、地图进入失败和挑战动作都有失败后重新绘制整个页面的出口。原存档事务即使未改任何数据，也会用回滚副本替换状态对象，使阵容查询缓存失效、原节点绑定引用过期。合成材料不足、余额不足、无效或过期奖励等正常拒绝因此被放大为敌阵重算及模型装配。

挑战中还有“余额不足”“人口已满级”等按钮在未执行领域操作的情况下仍调用 `act`，造成无意义的画布和计时器重建。

## 统一处理

事务快照现在同时记录 JSON 数据和对象引用次序。失败时只有数据、字段顺序、数组顺序及所有嵌套对象引用都未变化，才保留原状态；发生修改或同值对象替换时仍恢复完整快照。额外的失败比较只发生在异常出口。

界面只接受当前模型事务提供的证明，并核对动作起点、已提交版本、实际绘制版本和页面导航。无修改拒绝只显示轻量反馈；提示叠加在原操作面板上，关闭后恢复原面板，保留奖励候选、合成选择及滚动位置。有实际回滚、中途成功提交、旧界面版本或未知异常时仍重绘，以更新绑定。

历史最高关卡的动作前成绩改为只读采样，成功后再合并入事务，避免验证失败之前写入辅助字段；成功提交仍保留动作前后的最高成绩。开关及反馈布局集中在 `game/play/action-feedback-config.js`。

| 排查入口 | 最终处理 |
| --- | --- |
| 远征通用操作：合成、招募/刷新、奖励/福利、活动、商店 | 无修改失败保留场景和原弹窗，直接提示 |
| 经典页面通用动作、旧版动作入口 | 共用事务拒绝证明，使用轻量提示 |
| 地图节点进入 | 无修改失败仅移除“正在进入”文字，保留地图和滚动位置 |
| 穿戴装备、挑战穿戴 | 失败保留原角色/装备面板；真实回滚仍恢复显示 |
| 装备进阶详情 | 无修改失败保留详情和正文位置；保留原隐藏碎片提示配置 |
| 天赋树升级 | 无修改失败保留原加点面板，成功仍更新真实等级 |
| 挑战通用动作、准备计时失败、收取装备失败 | 无修改时只更新反馈，保留棋盘和计时器 |
| 挑战余额不足、人口 MAX、失效选棋点击 | 不再提交空动作，不重建画布 |
| 挑战拖出己方棋盘 | 原地回位并更新文字，不重建画布 |
| 合法成功操作、结算推进、真正回滚 | 继续按原业务流程刷新 |

商人列表和若干只读提示原本已只更新文字/局部弹窗，不再增加额外重绘。复活超时、放弃和真实战果结算属于有实际业务变更的流程，保留其结算刷新。

## 验证

- 全部回归 **986/986** 通过，新增 **22 项**专项测试，覆盖 12 类真实拒绝入口，以及嵌套引用替换、写盘失败、真实修改回滚、先提交后失败、过期画布、保留提示关闭、云同步拦截、地图滚动和挑战计时保留。
- 隔离 Node 样本：60 武将、18 装备，5 次金币不足刷新。旧 1.0.286 包路径每次均重建预览，中位耗时 257.502 ms；新路径中位 0.294 ms，场景重绘 0 次、写盘 0 次，状态引用保留。渲染替身仅运行真实敌阵查询，数据不等于手机触摸延迟。
- 正常提交的同机快照开销：无战报中位 0.211→0.245 ms；带战报 2.682→3.143 ms。记录引用有少量成本，未在该样本产生长任务；不由这些数据推断真机温度。
- 微信模拟器真实 Cocos 面板：金币不足、合成不足、装备不存在、进阶预期等级过期、未完成日常分别为 8/4/2/4/4 ms（处理及提示节点创建）。另验证待领取时关闭错误提示仍返回原面板。6 次均保留状态、面板和角色，无重绘及写盘；真实修改后失败对照组发生 1 次恢复重绘。玩家状态未变。
- 22 项发布模型检查、Babel 编译兼容检查通过；实体手机交互延迟和发热仍待复测。

证据：`evidence/tests-1.0.287.txt`、`evidence/action-failure-287-benchmark.json`、`evidence/action-failure-287-engine.json`、`evidence/models-1.0.287.txt`、`evidence/babel-1.0.287.txt`。

## 后续架构建议

保留本次“拒绝证明—版本检查—局部反馈”的共用出口，避免各按钮自行判断是否跳过重绘。对于采样确认仍高频或存档很大的拒绝，可继续提取共享只读预检，像满员拖拽一样在进入快照前返回；正式提交仍在事务内复核。对成功操作另行按状态差异拆分局部刷新，不能将无修改失败的策略泛化为所有失败都不刷新。
