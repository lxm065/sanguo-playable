# 首通增长与敌军机制预算优化

日期：2026-10-30。版本：1.0.282。

## 行为

首通从第4次正式连胜起的增幅下限改为：

| 章节 | 第4胜 | 第5胜 | 第6胜及以后 |
| --- | ---: | ---: | ---: |
| 1～3 | 12% | 15% | 18% |
| 4及以后 | 18% | 22% | 25% |

轻松获胜规则与上述下限取较大值；不是把两项相乘或相加。第4章起三档连续增长由原来的至少4.576倍改为约1.7995倍。不会按固定场数强制判负。

新关目标在统一战力预算中计算：棋子面板及已有装备评分，加上有上限的机制溢价。机制包括实际启用的每秒回血、部分已实现治疗/控制技能、重复钩人、格挡及高倍率主动爆发。单技能取最大成本标签，避免冰冻重复计费。当前机制溢价上限55%，是可调估算值，不是实战胜率预测，不宣称覆盖全部技能组合。

增加机制成本后，原目标总预算不变，由生命、攻击归一化倍率补偿，使高回复/强控制阵容不再完全按普通普攻面板估值。没有修改武将、装备或羁绊自身的技能数值，也没有增加人数、等级或装备槽位。

普通、精英、Boss继续使用原类型系数。对首通正常增长阶段，下一关总目标相对于最近实际通关总目标的跳升上限：1～3章25%，第4章起40%；包括连胜进度与关卡类型的合计变化。降低类型系数时不把敌军抬高。未有通关记录的旧档先沿用已有难度，取得一场新通关记录后可应用上限。

视频恢复阶段、已通关章节重玩不应用此跨关上限，保持原恢复目标/次数与重玩每胜加0.02规则。第一阶段保护、第二阶段首场普通关1.00且无装备、玩家基准不计算装备、最高等级/高级数量约束、全阶段视频机制援助保持既定规则。

已锁定敌军与待领战报不重算，升级后从新关卡开始使用预算估值；旧广告减难不会因升级被清除或加难。新增长策略在后续正式胜利生效。

## 可观测与实现

- `enemy-win-growth-config.js`：连胜档位与跨关跳升上限。
- `enemy-transition-budget.js`：只读跨关总目标约束。
- `enemy-mechanism-budget-config.js` / `enemy-mechanism-budget.js`：无战斗预演的机制估算，配置与计算分离。
- 锁定记录 `enemyEncounter.lightBalance` 记录 `budget.units/equipment/mechanisms/total`、`mechanism` 与 `transition`，可以定位卡点的预算来源；这些分项为同一总预算的拆分，不是额外叠乘倍率。

统一预算结构为后续阵容模板提供入口。后续若扩展治疗、控制、召唤和专属装备估值，应优先复用效果元数据并用多阵容实战校准，避免把技能ID判断散落到关卡生成代码。此次没有重写阵容模板或更改地图线路。

## 验证

全量936项测试通过：`evidence/test-final-1.0.282.txt`。覆盖跨关上限、预算分项、旧锁定快照、养成隔离、视频恢复、重玩与首通增长；不存在开战前多次模拟的等待流程。机制预算单独200次查询，本机均值约0.26ms，不能代替真机性能测试。

同一当前战斗引擎，切换旧/新增长与预算策略对照；各16条路线，章节1、3、4、8，裸装/固定配装两组、避精英/选精英两种路径、种子101。每组880个首次战斗节点：

| 指标 | 旧策略 | 新策略 |
| --- | ---: | ---: |
| 首次失败 | 298 | 193 |
| 累计减难视频 | 368 | 244 |
| Boss单关最多视频 | 3 | 3 |
| 达到10次视频上限仍卡住的路线 | 0 | 0 |

另对历史第4章第4阶段3个Boss阵容，用当前引擎、同目标、每档24个相同种子，独立验证机制预算。三个阵容计入机制后首次视频均24/24通关；对照未计机制组的首次视频均失败。只证明这些样本改善，不能宣称所有玩家1次必过或3次必过。

数据：`evidence/difficulty-optimization-1.0.282/results.json`、`summary.json`、`bosses.json`、`query-performance.json`。固定成长模板未包含实际奖励合成、商店道具选择、主公主动技能或完整长期养成，结果不是全体玩家胜率。

本轮同时修正路线诊断工具：每次重试重新读取援助快照，正式胜利推进援助恢复，防止使用战前旧快照而漏算视频的机制减难。新旧对照两组共用这项修正，历史1.0.221 HTML保留为旧报告。
