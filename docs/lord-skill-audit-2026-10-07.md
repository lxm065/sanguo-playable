# 主公技能实现审计（2026-10-07）

核对工程：F:/game/wow-zzq/sanguo-playable，main，当前源码版本1.0.64。工作区存在既有未提交修改。本次仅增加审计脚本、结果和报告，没有修改玩法，也没有重新发布。

## 结论

当前展示的七个一级技能只有刘备明确落实了效果，其余六位只有说明或基础初始数据，没有相应固有技能执行链。袁绍没有开战盗取装备逻辑，不是已实现但概率较低。

| 主公 | 展示效果 | 实现状态及依据 |
|---|---|---|
| 刘备 | 上阵单位+1 | 已实现：population.js:4读取classic.lordArmyBonus，刘备配置+1；独立档同等级人口3，其余主公2 |
| 孙坚 | 开局赠送可无限升级的祝福装备 | 未实现：progression.select/restart/claimSection只初始化生命金币，开局装备为0；现有equipment-upgrades是有上限的永久装备强化，不是此技能 |
| 董卓 | 进入BOSS、商店随机获得1件装备 | 未实现：progression.enter和NodeEvents.enter没有按主公发装备的分支；独立档商店入口免费装备为0 |
| 袁绍 | 每次战前概率盗取装备 | 未实现：Expedition.fight只接入天赋经济beforeFight，再调用基础战斗；没有袁绍盗取或发装备逻辑 |
| 曹操 | 每次战前加入1～2级单位 | 未实现：开战前没有按主公生成单位的处理；独立档开战单位数量不增加 |
| 孙权 | 合成概率返还单位、强化泉水 | 未实现：merge仅三合一、返还装备、处理天赋暂存；spring按共用规则只执行一次，不读取主公 |
| 刘表 | 两件蓝装换一件紫装 | 未实现：未找到对应交换入口或原子消耗、发奖事务；已有普通卖装备功能不等于此技能 |

## 高级技能与容易混淆的功能

classic-config.js / classic.config.json的source字段保留skill_des2、skill_des3和upgrade_id，但没有主公技能等级状态、主公技能升阶入口及对应效果分发。主公经验升级目前主要影响人口，不意味着固有技能升为Lv.2或Lv.3。不能把source中高级说明视作已经实现。

主公选择、解锁、初始生命和金币已接入。lord-blessing-config.js所定义的战败视频召唤2级武将是通用祝福，独立于袁绍盗取、曹操征召等固有技能。

## 验证方式

运行 `node evidence/lord-skill-audit.cjs`。每位主公用32个不同种子建立全新内存档，调用真实开战和合成入口（战斗模拟器使用固定胜利回报，专门隔离开战触发），同时检查选择主公后的初始装备和商店进入奖励。七位均无战前装备/武将增加，合成后均只剩1名单位；刘备人口多1。

概率抽样零触发本身不足以证明缺失，本报告同时检查了源码调用链与全部主公相关读取位置。所有测试均不读写微信真实存档，也不等于真机验收。原始结果：evidence/lord-skill-audit.json。

## 后续实现建议

建立配置驱动的主公技能领域服务，将开局、进节点、开战前、合成后、泉水和装备交换分别接入既有事务；用远征/节点/战斗唯一标识防止重进刷奖励，并保存已抽取的结果。显示文案与技能等级应由同一规则查询生成。补测失败回滚、重载、重复点击、备战席满、已装备物品交换限制。

原配置仅写“有概率”“泉水更强”，缺少一级盗取概率、合成返还概率、祝福装备升级成本与效果等明细；需要核对原版或明确采用本地可调规则，不能把猜测数值冒称复刻值。

## 本次实现更新（1.0.65）
袁绍、曹操的一级技能已接入正式远征战斗事务；上文为改动前审计快照。袁绍采用本地可配置30%概率，从现有蓝装权重池发放一件装备（原资料没有准确概率，此值不宣称原版数值）。曹操每场招募一名已解锁的1～2级武将，默认放备战席，有限容量满员时进入待入队队列。演武、多人挑战不触发。
