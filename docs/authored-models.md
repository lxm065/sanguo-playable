# 四位武将模型补齐

> 历史方案：用户反馈外观后，四位英雄已改用魔兽世界资源。本页记录的原创建模源文件保留，当前游戏结果与验收以 [魔兽资源版本](wow-models/README.md) 为准。

已将太史慈、甘宁、张角、颜良接入 `game/play/battle-appearance.js`，21 位图鉴武将均具有战斗模型。这四位采用原创低多边形网格和关节动画，不是其他英雄换名，也不是头像平移。

| 武将 | 外观 | 三维网格数量 |
| --- | --- | --- |
| 太史慈 | 铜盔白羽、暗红甲、长弓与箭囊 | 90 |
| 甘宁 | 青色头巾、蓝绿轻甲、铜铃、双刀 | 83 |
| 张角 | 黄巾道袍、长须、木杖与符带 | 48 |
| 颜良 | 紫黑重甲、铁盔紫缨、长柄刀 | 81 |

每位均有待机、移动、普通攻击、技能、死亡五套动作，五个独立渲染方向加三个镜像方向，320 帧、25 条游戏动画、两张压紧图集。游戏仍使用既有 Cocos Spine 附件动画管线；GLB 作为可编辑的三维源模型保留，不在游戏中引入新的三维引擎。GLB 使用关节层级控制刚体网格，尚不是连续蒙皮的人体模型。

## 文件与重建

- `source-assets/authored-models/*.glb`：四位可编辑模型与五套关键帧动画，可导入支持 GLB 的三维工具。
- `tools/authored-models.mjs`：网格、关节和动画制作代码。
- `tools/authored-models.config.json`：身份、配色、身形、武器、动作时长、镜头及本机依赖配置。
- `game/skin-assets/battle-{英雄ID}*`：游戏使用的图集、Spine JSON、动作与来源清单。
- `game/play/body-center-config.js`：躯干中心标定。
- `source-assets/portrait-manifest.json`：保留原有头像及来源，模型待制作标记已清除。

按实际安装位置配置 Three.js、Puppeteer 和浏览器路径后运行：

```powershell
node tools/build-authored-models.cjs
node tools/compact-battle-atlases.cjs
node tools/calibrate-body-centers.cjs
node tools/battle-model-report.cjs
node tools/build-wechat.cjs
```

仅重建指定英雄可向第一个命令传入英雄 ID。三维源文件保存在源码目录，发布包只带烘焙后的游戏资源。

## 验证边界

- 四份 GLB 的文件结构、网格、动作关键帧及 SHA-256 与烘焙清单一致。
- 四位共 1280 帧图集均未触碰原始画布边界；镜头根据所有动作和方向自动适配。
- 模型覆盖、动作、头像摘要、布局和战斗 HUD 共 18 项相关测试通过；最后一轮方向修正后重新验证 12 项受影响测试。
- 微信开发者工具成功解析四位模型，逐一创建共 100 条方向动画。临时展示层的前后玩家状态一致。
- `evidence/authored-models/runtime.json` 为引擎验证结果。最后一轮方向修正后的异步模拟器复验出现超时，因此不将旧截图作为最终方向验收证据；`docs/battle-refinement/models-overview.png` 是最终烘焙模型总览。临时展示层已清理，玩家状态复核未改变。
- 最终开发包位于 `dist/wechat`，构建体积 31,218,066 字节，主包 2,236,286 字节，通过当前项目配置的包体上限检查。该包包含工作区原有改动，未单独上传。

## 后续架构建议

当前模型配置、图鉴和来源清单仍各自维护英雄身份。下一步可建立统一资产注册表，按英雄 ID 声明源模型格式、动作契约、头像来源和烘焙结果，并让配置与包体白名单由注册表派生，避免再次出现头像已完成但模型状态未同步的问题。

烘焙入口已复用同一 `pack/bounds` 实现。继续演进时适合将 MDX 与原创 GLB 作为独立渲染适配器，共享图集打包、裁切检查和清单验证；这样替换美术源文件不必修改游戏加载器或战斗规则。

美术精修可在现有 GLB 上补充手绘纹理、弓弦拉伸和更细的腕肘动作；需要更柔顺的人体动作时再引入蒙皮骨架，保持五套动作及方向命名契约不变。
