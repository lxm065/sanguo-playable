# 1.0.159 地图与开战性能

排查近期变化：1.0.150 增加持有阵容及配装的最强战力搜索；1.0.156 引入分叉路线；1.0.157 战斗只读入口；1.0.158 第一节经验调整。

实际发现和修正：
- 地图资源预载回调调用 model.enemies()，导致尚未进入战斗时触发整支敌军生成和最强阵容搜索。改为只预载己方及已保存敌阵，执行前先检查页面生命周期。
- 最强阵容搜索重复计算同队羁绊与同装备进阶属性。新增仅在一次静态搜索内有效的缓存，不用于正式战斗的可变状态。
- 最强阵容单槽缓存会被不同规则上下文互相覆盖。改为最多4份、按完整输入及 roster 隔离的缓存，培养或装备变化仍重新计算。
- 敌人生成按每名武将反复查询相同最低等级，改为同次生成复用；等级分配与装备补偿共用一次参考查询。
- 分叉图连通判断重复扫描边，改为按路线快照缓存邻接集合。

验证：缓存与未缓存的评分和虚拟阵容逐字段一致；规则上下文交替不抖动且装备变化失效；路线连通与完整小节推进检查通过。
模拟器当前5武将4装备：首次单次最强阵容查询127ms→24ms。隔离的第二节模拟：强阵容查询89次→32次，最终敌阵预览43ms、开战84ms（中间版本开战118ms）；时间含模拟器噪声，不等于真机帧率承诺。实际玩家存档未用于试打。
完整回归仍有第三章装备解锁断言失败，未修改其规则，详见 evidence/tests-1.0.159.log。

长期建议：把敌军预览、资源预载与正式开战的职责保持分离；阶段性记录耗时和缓存命中，后续若大量武将/装备仍有长任务，再把静态搜索拆成可取消的分帧准备任务。
