# 1.0.7 宝藏状态、敌方阵型与战斗特效

## 实现
- 宝藏只有真实行军记录标为完成才使用开启贴图；可进入但未领取时保持关闭亮态，未经过保持灰态。
- 敌阵共用纯函数排布，按当前阶级实际射程区分前后排，优先中间列，格子占用时回退到下一排。普通敌人与配置 BOSS 均走此规则，不改变阵容身份、数值或随机种子。
- 将魔兽争霸 RingOFire、Shockwave_Ice、LightningBall，魔兽世界 frost2、holyfire，以及英雄联盟 Lux 目录下 starfilter 实际贴图适配为六张透明小图。完整来源及 SHA256 见 source-assets/battle-effects.json。
- 按武将配置冰、火、圣光、暗影、毒等风格，接入真实 attack / damage / heal 事件，覆盖施法圈、飞行弹道、普通命中、技能命中和治疗。此为原贴图的二维分层适配，不是完整移植原游戏三维粒子系统，也不新增战斗规则。
- 特效预热并复用资源缓存，同时限制 32 个节点；结束或离开战斗清理节点和补间。所有风格、尺寸、生命周期、节流及阵型优先级集中配置。

## 验证
- 全套 139 项测试通过；发布构建主包 2,304,700 字节、总包 31,241,534 字节，低于现行项目体积限制。
- 发布包与当前源码同步验证通过。
- 开发者工具隔离存档确认许褚前排、小乔和周瑜后排；真实战斗技能伤害事件 t=3.4 触发六个特效节点。分层效果另做模拟器静态帧检查。
- 已打开宝藏地图截图 evidence/opened-map-107.jpg；阵型 evidence/enemy-formation-107.jpg；特效帧 evidence/effects-verified-107.jpg。
- 验收脚本曾因暂停渲染及读取已销毁节点导致黑屏，已修正验收操作并恢复。此异常来自调试脚本，不是发布代码。玩家实际状态恢复前后相同。
- 模拟器检查不等同手机性能验收；真实多人密集技能与低端机帧率仍需手机体验验证。

## 后续架构建议
当前通过独立阵型策略和独立战斗表现层隔离规则，后续应给战斗事件补充配置化 effectKey / hitPhase，避免只按武将推断所有技能视觉。再按性能证据决定是否引入节点池；目前不为小量瞬时节点增加复杂对象池。
