# 1.0.301 成功操作局部刷新

日期：2026-11-12。

## 确认的问题与处理

`ExpeditionView.act` 在成功事务后无条件调用整页 `render()`，普通领奖、换一批、合成、布阵和福利到账都会销毁背景、角色外层节点、资源栏及操作栏。此前的身体复用只能减少部分骨骼重装配，不能避免整个节点树重建。

新增 `battle-refresh.js` 作为成功出口：核对领域模型、状态引用、绘制版本、当前页面、章节及场景锚点，再按区域同步。开关放在 `interaction-performance-config.partialBattleRefresh`，关闭可恢复原成功重绘路径。状态写入、随机种子、战报和奖励规则不变。

| 入口 | 当前刷新范围 |
| --- | --- |
| 战斗选将、装备领奖、放弃选将、演武继续 | 保留背景、主公头像、资源标签、操作栏和未变化备战武将；战后角色恢复布阵绑定、原站位及正常血条；同步实际新增武将和装备 |
| 战果“换一批” | 重建候选弹窗，保留全部战后演员及战报；新按钮重新绑定刷新凭据 |
| 领奖带来的主公升级 | 原地更新等级、经验、人数、金币及提示；“开始/前进”回调实时读取当前节点 |
| 原地、随机、定向合成 | 删除材料演员，替换升阶/变身演员；刷新羁绊、合成标记、装备归还及备战分页 |
| 布阵交换、同格释放 | 相同显示倍率的既有演员原地移动；取消拖动读取最新的返回坐标 |
| 备战席合成后补位 | 保留仍可见且身份/阶级未变的骨骼，仅移动坐标；新入可见页的角色才创建节点 |
| 招募、福利和普通战斗页资源操作 | 复用同一成功差异出口；福利广告凭据变化时更新对应区域 |
| 合成返回、定向取消、装备背包返回 | 只撤去模态遮罩 |
| 成功开始战斗 | 开战已有专用场景建立流程，通用动作不再重复执行页面清理 |

装备穿戴、装备进阶详情和天赋树加点原本已在背包/图鉴/天赋窗口内局部更新，保持这些既有入口。战斗回放开始/结束、跨章节、换页面、商人/泉水/宝藏事件场景、挑战模式，以及状态回滚或旧画布，继续使用各自完整刷新出口；本次没有把普通备战页面的复用策略套到不同生命周期的场景。

## 一致性约束

- 不单靠 JSON 相等判断演员可保留：同值武将对象替换也重新绑定，避免保留旧触摸闭包。
- 角色外观和显示倍率决定是否重建，格子变化由位置更新处理；拖动回位坐标随站位/手牌补位更新。
- 区域删除先脱离父节点，再请求 Cocos 延迟销毁，避免同一帧命中旧节点；记录原层级，保持角色、HUD 和模态层顺序。
- 消耗材料的装备同步回到背包，穿戴徽章先移除旧行，避免重复图标。
- 局部更新完成后同步绘制版本，使前一版的“无修改失败直接提示”仍可正常工作。
- 敌阵输入变化时继续调用原查询，保留现有锁敌和难度机制；未变化的敌军演员按外观复用。

## 验证

全量回归 **1088/1088** 通过；新增 **15 项**专项测试，覆盖真实奖励/合成/布阵事务、存档等价、同值引用替换、随机和定向凭据、材料装备回收、末页夹紧、补位后拖动取消、写盘失败、旧画布和导航回调。

Node 使用 60 武将、18 装备及已锁定敌阵，调用真实领域和布局逻辑、轻量节点树，每种路径各 5 组对照，最终保存数据逐组一致、每次写盘均为 1 次：

| 操作 | 原整页重绘次数 | 现整页重绘次数 | 原演员创建调用 | 现演员创建调用 |
| --- | ---: | ---: | ---: | ---: |
| 合成（场上材料样本） | 1 | 0 | 22 | 1 |
| 奖励换一批 | 1 | 0 | 13 | 0 |
| 领奖恢复布阵 | 1 | 0 | 14 | 8 |

这里的演员创建是外层控件创建调用，不等于新 Spine 资源加载数。轻量 Node 替身没有 GPU 和骨骼装配成本，不能据其毫秒值推断手机提升：局部比较本身有少量 CPU 开销，本次主要减少真实引擎节点销毁、布局、绑定及装配工作。

真实微信模拟器使用独立 Cocos 场景和内存存档，完全不初始化账号/云存档、不读取玩家保存数据。通过正式按钮事件验证合成、同格释放、换一批和领奖升级，核对节点及骨骼身份、资源标签、死亡棋子恢复和写盘次数；画面由测试自己创建的画布导出 PNG。最终报告在 `evidence/battle-refresh-301-engine-1794444694438`：四次操作整页重绘均为 0、写盘均为 1；同步处理耗时分别为 54/4/12/33 ms，演员创建数为 3/0/0/9。该合成样本包含两名备战材料，3 次创建分别对应升阶演员和补入当前可见页的两名武将；领奖样本还包含升级提示中的装饰 NPC。已查看导出画面，战后人口从 8/8 更新为 8/9、主公等级更新为 9，按钮更新为“前进”。这些是模拟器样本，不等于手机触摸延迟、持续帧率或温度，仍需真机复测。

证据：`evidence/tests-1.0.301.txt`、`evidence/battle-refresh-301-targeted.txt`、`evidence/battle-refresh-301-benchmark.json`，以及版本对应的模型/Babel/构建/上传报告。

## 后续维护

新增普通战斗页操作应进入统一差异出口；新的事件页或挑战页面应先定义自己的区域和计时器生命周期，再接入局部刷新。渲染完成标记与事务版本必须同步，不能用“操作成功”直接推断所有旧界面仍有效。
