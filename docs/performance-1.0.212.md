# 合成及战斗准备开销优化（1.0.212）

发现两处可确认的开销：不可达敌人触发重复全棋盘 BFS；节点销毁后的模型装配仍需逐个等待队列延迟。

- 搜索改用数字格索引、数组游标及占位表，保留原有邻居排序。
- 首选敌人不可达时复用完整可达区域筛选其他敌人，仅为一个可达备选再搜路径，避免对每名不可达敌人重复 BFS。
- FrameQueue 接收有效性检查，已销毁节点的待装配任务立即跳过；已排定任务执行前再次确认节点有效。
- 武将装配提交实际节点有效性检查；没有取消有效模型解析任务，不改变资产缓存和奖励事务。

证据：evidence/targeting-perf-212.json。1000组随机场景的 nextStep 和 approachStep 与优化前结果一致；同一堵路场景3000次搜索由约339ms降至29ms。此为本地Node基准，不是手机帧率或整场战斗耗时。

队列测试覆盖20个过期任务一次跳过、有效任务继续、排定后失效及错误恢复。真机首次模型解析与GPU装配耗时仍待实际设备验证。

后续优化建议：测量合成后的整屏重建成本，再将未变化的战场武将改为增量更新；不在缺乏实测时大范围重写UI生命周期。

发布验证：743项测试、22项模型检查通过，微信开发版1.0.212上传成功（exit 0 / √ upload）。未声称真机性能验收或正式发布。
