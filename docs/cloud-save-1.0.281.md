## 玩家行为

- 启动必须完成微信账号登录和云端读取；网络失败提供重试，不将读取失败当作没有存档，不生成临时空档继续游玩。
- 首次接入将现有有效本机战役导入账号云档；换设备时优先恢复云端已经确认的进度。
- 本机和云端出现不同分支时先保存恢复包，再明确选择“恢复云端”或“保留本机”。不按设备时间、章节或钻石自动挑选一份，也不合并奖励和货币。
- 本机主档损坏时检查上一份有效备份；两份本机档损坏但有有效云档时恢复云端。损坏数据保留；没有可用恢复记录时停止，不清空新开。
- 头像面板显示真实同步状态和“同步存档”入口；本机保存与云端确认分别显示。
- 新启动取得有效会话后，旧会话立即不能调用后台受保护接口。旧端通过 15 秒心跳、前台恢复和保存请求发现撤销后锁定事务并提示退出，后台重试不会抢回登录。
- 网络异常暂停操作，恢复连接后继续发送持久日志中的同一提交。心跳和会话租约时长可配置。

## 一致性与恢复

`storage.js` 继续承担同步本机写盘和失败回滚。`Campaign.transact` 在执行操作前检查存储端口的会话权限，`Expedition` 转发权限检查，避免先执行发奖副作用后才发现账号无效。

`cloud-save.js` 单独协调同步日志、版本、冲突和幂等重试；`backend-session.js` 仅管理内存令牌与经过旧令牌证明的同机续期；`cloud-save-ui.js` 负责原生提示与头像面板。`cloud-save-bootstrap.js` 在隔离存储中复用真实领域构造器进行兼容迁移和校验，然后才安装进度和创建操作界面。

服务端使用已有 MySQL 云存档表及玩家会话表。所有写入具有基础版本和提交号，先持久化完整请求再发送，未知结果复用提交号。客户端保存期间发生的新操作进入下一批，不修改在途请求。服务器保留最近五份云端快照。

服务端除 HTTP 鉴权外，在存档事务内锁定并核对当前会话，与新登录的会话替换争用同一行锁，覆盖“请求鉴权之后被顶号”的竞争窗口。基础版本不符返回冲突，旧端无权覆盖新端进度。同机续期进行会话比较交换，不能替换已经生效的新设备会话。

本机恢复包按玩家隔离，保留主档、备份、同步日志及冲突时的云端快照；只保留最近一份恢复包以限制容量。令牌不进入本机存档、同步日志、截图或验收回执。

## 验收边界与演进

后台即时撤销旧令牌不等于旧设备画面即时关闭；客户端检测存在心跳窗口，服务端始终拒绝已撤销会话的写入。换机只能恢复云端已确认的数据，尚未上传的最后操作保留在原设备，重新进入时通过冲突选择恢复。挑战模式仍按既有配置仅保存棋组、积分，当前棋局不跨运行续局。

手机双端互踢、弱网切换和清缓存后恢复仍需实际设备验收；模拟器和测试通过不能代替此项。微信开发上传不等于审核提交、体验版设置或正式发布。

长期应保留现在的存储、会话、同步协调和 UI 边界。若增加服务端建筑或经济结算，将其接入独立领域命令和同一版本事务，不继续向视图或通用存储函数加入账号分支。当前同步日志完整保存确认快照以进行无损比较；存档变大后可在保留恢复保障的前提下引入独立日志封装及经验证的完整性摘要。资源包距离总量上限约 30KiB，后续扩展前应规划资源裁剪或按需分包。
