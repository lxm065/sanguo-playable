# 1.0.279 异常退出后的战果恢复

2026-10-30：修复异常退出后进入路线地图、点击节点只提示“请先领取本场结算”的阻塞。新版本读取原有待领取战果，优先恢复到战场领取界面，玩家继续选择武将或领取装备；不重新模拟战斗、不自动放弃候选、不重置存档。

## 原因和修复

- 原战果已在开战时持久化，但视图启动仍停在首页，当前章节入口允许切到地图。地图上的 `Progression.enter()` 正确拒绝修改待结算状态，视图却只显示提示，没有恢复领取入口。
- `battle-recovery.js` 集中处理待领奖的导航优先级。`ClassicView.render()` 在页面分发前恢复领取页；地图旧控件回调也先检查战果，避免重新进入节点并再次报错。
- 正在回放或创建战斗画面时不抢占导航。普通胜利继续使用原来保存的选将、金币和经验；精英装备继续通过原事务入库；战败、平局、演武与章末仍走各自已有结算流程。
- 错误提示关闭后，若战果仍待领取则重新绘制领取界面。写盘失败可以重试，旧提示的迟到关闭回调不会移除新弹窗。
- 恢复开关位于 `game/play/expedition-config.js` 的 `pendingRewards.resumeOnRender`，默认开启。本次不修改存档格式和领域层的防重复领取约束。

## 后续架构优化

1. 当前 `PlayView` 构造器调用可覆写的 `render()`，后续 `ClassicView` 构造器还会再次渲染，视图初始化存在重入。建议将依赖装配和首次呈现分成显式 `initialize()` / `mount()` 生命周期：先绑定进度、广告等端口，再呈现一次。验收应检查章末自动结算、复活倒计时和进场技能在初始装配期间只触发一次。
2. 战果、章节奖励、远征结算、扫荡和错误提示共享单一 `modal`，互相覆盖后依赖各页面自己恢复。建议引入只读取持久状态的奖励路由解析器，返回确定的呈现类型与稳定奖励标识，由统一弹窗宿主负责打开和恢复。领域领取事务继续保持原子性；视图不承担发奖或存档迁移。
3. 保留当前内存存储回滚测试，并增加原生触控与重启场景的自动验收：覆盖真实触摸开始/结束、按钮失焦、重建视图和错误提示关闭。控件回调测试验证事务出口；原生触控测试验证命中框和事件链，两类证据分别记录。本次不扩大到全局输入系统重构。
