# 大量手牌预备开销（1.0.233）

原备战预热扫描全部可合成武将并请求其下一阶外观，未翻到的手牌页也会触发模型读取及解析。手牌类型增加后，后台资源工作随之增加；同一页每个名字又重复计算一次全量合成提示。

- 只预备当前手牌页及上阵单位，当前页优先；按实际外观键去重。
- 每轮最多预备3种合成模型，通过 battle-panel-warm-config.maxMergeModels 配置。
- 翻页使旧预备队列失效，并安排新页预备。不会取消已经开始的单个资源读取。
- 同页姓名提示复用一次 eligible 查询；查询内部只读取一次阶级上限。
- 不限制手牌容量，不改变合成、战斗、奖励或存档规则；未预备的外观仍可按需加载。

验证增加300张手牌场景，检查预备范围、数量上限、阶级查询次数、只读性及翻页取消。真实手机的持续战斗帧率与整屏重绘耗时仍待设备验证；不能由预备任务数量直接推断帧率。

后续建议：按实机采样区分模型更新、整屏重绘与战斗演算耗时，再决定是否采用增量刷新或按可见性暂停动画。

发布验证：805项测试与22项模型检查通过，微信开发版1.0.233上传成功（exit 0 / √ upload）。真机性能尚未验收。
