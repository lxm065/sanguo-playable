# 战斗场景交互修正

- 武将轻触直接进入详情，删除底部独立“武将详情”按钮。合成仍在详情里进入；拖动武将继续布阵。
- 羁绊改成固定尺寸、单字徽章和独立人数角标，点徽章显示完整名称和效果。八种同时显示不会挤出预留区域。
- 闲置装备直接显示在底栏，最多两行，超出时翻页。点击看说明，拖动给己方单位；上阵区和当前备战页都可穿戴。已穿戴装备同时显示在单位血条上方。
- 拖动时原位图标隐藏，显示浮动图标与金色“推荐”。推荐来自原装备 `recommend_1..10` 字段与已确认三国映射，不靠头像或职业猜测；满三件的单位不会被推荐。推荐不限制玩家自由选择其他武将。
- 空白/敌方落点和系统取消不改变装备，放到满槽武将时保留原物品并提示。处理了 Cocos 节点外松手被转换为 `TOUCH_CANCEL` 的行为，通过原始 `getEventCode()` 区分真实取消与松手。
- 点击主公头像展示名字、头像、等级、当前经验/门槛、可上阵数量、主公技能和“换一批”概率。读取实际领域配置：当前二阶为100%，三/四阶显示“暂未开放”，不虚构尚未接入的8/12级掉落规则。点击弹窗外关闭。

## 验收

52项测试通过（原46项回归 + 6项战斗栏测试）。新增覆盖推荐只读/满槽过滤、命中范围、八徽章与两行物品边界、概率一致、推荐身份、节点外松手与真实取消。

微信开发者工具实际触摸验证：点击武将详情、点击主公属性、拖动显示推荐、龙心穿戴上阵许褚、先锋盾穿戴备战许褚、空白放回、再次拖动成功。验收使用 `tools/battle-hud-qa.cjs` 建立的内存阵容和物品，未改玩家存档；结束比较原状态相同并恢复首页。未执行微信上传，未进行手机实测。

## 代码职责与后续优化

`battle-hud-config.js` 集中布局、徽章、推荐名单；`battle-hud-query.js` 提供只读推荐、命中和主公数据；`battle-hud.js` 管理视图和临时拖动节点，穿戴仍调用已有 `Expedition.equip` 事务。不修改掉落、装备属性或战斗效果。

下一步值得将棋子和装备拖动共同的坐标换算、触点归属和取消处理提取成一个拖动会话组件，再为多指输入与切后台补充自动化用例；避免两处手势逻辑随新功能分别演进。
